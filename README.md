# Work Experience: Software Engineering Programme

Welcome to two weeks of building real software.

This repository contains everything you need: guides to get set up, background on how software teams work, and ten project briefs covering a range of subjects and difficulty levels. By the end of the fortnight, your team will have designed, built, tested, and presented a working web application.

## Quick start

**Day 1, first thing:**

1. Read [intro/01-welcome.md](./intro/01-welcome.md) — 15 minutes, ideally as a team
2. Follow [intro/02-tools-and-setup.md](./intro/02-tools-and-setup.md) to get your machine ready
3. Read [intro/03-working-as-a-team.md](./intro/03-working-as-a-team.md) together and agree on your workflow
4. Read [intro/04-using-ai-as-a-developer.md](./intro/04-using-ai-as-a-developer.md) individually
5. Browse [projects/README.md](./projects/README.md) and pick your project

Once you've picked a project, open its README and get going. The day-by-day plan inside will guide you through the rest of the two weeks.

---

## What you'll have at the end

By Day 10, every team will have:

- A **working application** — something real that runs in a browser
- A **GitHub repository** — with meaningful commit history showing who built what
- A **README** — explaining what the project is and how to run it
- A **five-minute demo** — walking through the app and explaining the key technical decisions

This is exactly what a professional engineer would deliver at the end of a sprint. You're not doing a watered-down version of software engineering — you're doing the real thing.

## A note to teachers and mentors

Each project brief is designed to be self-contained: a team of three or four students with no prior experience can pick one up and build it in two weeks with appropriate support. The briefs include:

- A clear MVP (Minimum Viable Product) definition so students know what "done" looks like
- Day-by-day plans broken down by role
- Specific learning outcomes (technical and transferable)
- Stretch goals for teams who move faster
- Concrete first steps to avoid the "blank page" problem

The intro guides cover everything students need to get set up and collaborate effectively. You do not need a Computer Science background to support students through this programme — the materials are designed to be self-guiding.

If you have questions or find issues, please open a GitHub issue or contact the programme organisers.
